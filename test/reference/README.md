# External and independent reference regressions

These fixtures are deliberately not produced by `MultifieldInflationLattice`.
They are regenerated by the standalone Python program
`generate_reference_fixtures.py`, which imports only the Python standard
library and contains its own adaptive Dormand--Prince 5(4) integrator.

## Pinned external source

The single-field convention oracle is the source archive of
[InflationEasy](https://github.com/caravangelo/inflation-easy) at commit
`d4f0cfdde0d148fa8ffaa14fe37d705cd79b2366`. Exact SHA-256 digests of the
files read from that archive are in `PROVENANCE.toml`. The transcribed source
locations at that commit are:

- `src/evolution.cpp:419-516`: scalar and scale-factor right-hand sides;
- `src/evolution.cpp:129-145`: gradient and kinetic energy;
- `src/potential.cpp:151-170`: volume-averaged potential energy;
- `src/output.cpp:34-146,297-325`: shell membership, multiplicity, FFT
  normalization, and spectrum output;
- `src/output.cpp:271-289`: the physical Hubble conversion;
- `src/parameters.h:79-90`: `rescale_s` and `rescale_B` conventions.

`single_field_background.csv` specializes InflationEasy's documented custom
analytic-potential hook to a quadratic potential and sets `rescale_s = 0`.
The generator evolves the homogeneous specialization of the cited
InflationEasy RHS, including

```
phi'' = -2 (a'/a) phi' - a^2 dV_code/dphi
a''   = a^3 V_code - a'^2/a
```

with a Friedmann-constrained initial `a'`. The package under test is never
imported by the generator.

`single_field_conventions.csv` fixes a nontrivial `B = 0.25`, a one-mode
field/velocity lattice, all three internal energy components, and the exact
InflationEasy r2c shell average for that plane wave. It also records the
dimensionless package convention obtained from the independently computed
dimensional spectrum.

## Public-page and independent two-field references

The requirements also cite the public Notion page
[§6. 4次 Runge—Kutta による常微分方程式解法](https://pie-supply-358.notion.site/6-4-Runge-Kutta-c969f1759b8b4d9a894506418c6dda7f).
`PROVENANCE.toml` pins the page id, API-snapshot digest, retrieval date, and
the five exact block ids used. `notion_background_rk4.csv` transcribes the
page's two-field background algorithm exactly: masses `(9e-6,1e-6)`,
`phi=psi=13`, zero background velocities, classical RK4, and one outer step
of `dt=0.01/H` at a time. The regression compares this coarse page trajectory
with the package's finely integrated physical homogeneous trajectory using the
predeclared `2e-8` relative and `2e-10` absolute tolerances.

InflationEasy is single-field, so it cannot supply a two-field trajectory.
`two_field_background.csv` is intentionally a separate oracle: the same
standalone generator integrates the canonical two-field homogeneous
Klein--Gordon equations and the Einstein acceleration equation directly,
using its adaptive Dormand--Prince method. This tests the multifield
generalization without copying the Julia RHS or its RK4 stages. Its initial
data are the supplied acceptance example and the checked-in
`configs/two_field_quadratic.toml`: `phi = psi = 13`, physical masses
`(9e-6, 1e-6)`, physical velocities `(1e-10, 0)`, `a = 1`, and
`B = sqrt(V(phi,psi))`. The page's perturbation example, unlike its background
example, uses the small physical velocity `(1e-10,0)`; this specification
fixture keeps that case separate from the page's exact zero-velocity RK4
fixture. No external two-field InflationEasy table exists, because the
external code is single-field; the adaptive fixture is explicitly the
independent oracle for that otherwise unavailable comparison.

## Convention differences and excluded claims

- The pinned archive's current built-in choices are a tabulated USR potential
  and an analytic hilltop potential. The Julia package implements separable
  quadratic potentials. Therefore these files are **not** claimed to be
  output from the unmodified InflationEasy executable. They are a traceable
  quadratic specialization of its public custom-potential interface and
  numerical conventions.
- InflationEasy writes a dimensional shell average
  `P_phi = (L/B)^3 <|FFT(phi)|^2>/N^6` and labels a shell by
  `2*pi*bin/L`. This package writes
  `Delta^2 = k^3 P_phi/(2*pi^2)` and uses the mean actual momentum of all modes
  in the shell (optionally the seven-point-lattice momentum). The fixture
  stores both quantities and the test applies this conversion explicitly.
- The pinned `src/output.cpp:1004-1018` multiplies each internal energy by
  `B` in `results/energy`, whereas the supplied project specification defines
  physical energy density as `rho = B^2 rho_code`. The regression therefore
  checks InflationEasy's internal energy functions and separately checks the
  specified `B^2` conversion; it does not treat that output column as a
  physical-energy oracle.
- No stochastic realization is compared bit-for-bit across C++ and Julia RNGs.
  Bunch--Davies Hermiticity, variance, derivative phase, and independence are
  covered statistically in `test/unit/bd_statistics.jl`.

## Reproduction and comparison

From the package root, with any Python 3.9+ interpreter:

```text
python test/reference/generate_reference_fixtures.py
git diff --exit-code -- test/reference/*.csv
julia --project=. -e "using Pkg; Pkg.test()"
```

The generator overwrites only the four CSV fixtures beside it. A clean
`git diff` proves that the committed fixture values are reproducible. Tests
read the committed numbers; fixture generation is never performed during
`Pkg.test()`.
